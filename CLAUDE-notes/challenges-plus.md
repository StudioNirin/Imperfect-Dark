# Challenges+

A second, independent 30-challenge mode that starts as an exact copy of the
stock Combat Challenges but is edited separately. See
[challenges+ docs](../ImperfectDark-Docs/challenges+/) for the per-challenge
data and [custom-challenge-template.md](../docs/custom-challenge-template.md)
for the field reference.

## The three parallel datasets

- `g_MpChallenges[]` / `g_MpChallengesPlus[]` - the 30-entry registries (name,
  confignum, availability, completions, unlockfeatures). Plus is defined in
  `src/game/challengeplus.c`.
- `g_MpConfigs[]` / `g_MpConfigsPlus[]` - the 44 setups; Plus in
  `src/game/mpconfigsplus.c`. The 30 challenge records are indices `0x0e..0x2b`.
- `mpstrings` / `g_MpStringsPlus[]` - descriptions and bot names; Plus in
  `src/game/mpstringsplus.c`, seeded from the English `mpstringsF`.

`g_ChallengeMode` (0 stock, 1 Plus) selects the active dataset. Set by the
Combat Simulator's "Challenges+" menu row (setup.c) and carried in net RULES
(protocol 39). `challengeActiveList()` returns the active registry; all
completion get/set APIs route through it. Names for Plus are generated
("Challenge+ N"), so no new language strings were added.

Both the online picker and the offline entry lists show a right-column
description that follows the highlighted row, and select a challenge on a
single click - there is no confirm popup; Back (B/Escape) leaves without
changing the selection. The offline lists share `g_MpChallengesMenuItems`
and `mpChallengesEntryListHandler` (setup.c); the online picker has the
equivalent in netlobbymenu.c. The offline Plus handler must set mode 1 AFTER
calling the stock OPEN handler, which resets mode to 0.

## Save format

The GAME note's body is 0xa0 bytes and the stock bitstream fills all but three
bits of it, so an earlier attempt to append `30 * 4` completion bits and
`30 * 4 * 3` medal bits to `gamefile.c` was cut off by `pak.c`: the medals never
reached disk and stars came back bronze after a reload. Do not put Plus records
back in the GAME body.

Stars now live in `challengeplus.bin` beside the other save files - see
[save-format.md](save-format.md) for the folder. `port/src/challengeplus.c`
writes a versioned file with one block per agent, keyed by the GAME note's
`{deviceserial, fileid}` and checked against the agent name so a reused fileid
cannot inherit old stars. A block holds `30 * 4 * 3` bits: 0 is no record, 1-4
are bronze through perfect. `gamefileLoad()`/`gamefileSave()` call the helper;
a missing or damaged file reads as blank progress.

## Rules

- Only a challenge whose template has been renamed to `challenge+-NN.md` is
  listed; `g_MpChallengesPlusConverted[30]` is generated by the importer. This
  is authoring state, not an unlock, and is the same on every machine.
- `challengeRecordTier()` clamps the human count for the grader and both
  marking paths. `PLAYERCOUNT()` counts `g_Vars.players[]`, which holds humans,
  not the simulants in `g_MpSimSlots[]`; a sim-heavy challenge never inflated the
  record tier. The guard that discarded a mark whenever `PLAYERCOUNT()` passed
  four is gone - it was there for rooms with more than four humans - and the
  per-player bits are now written only for slots that fit in the byte, since
  `2 << mpindex` would otherwise spill into the next tier and the medal bits.
- A Plus completion ticks the Plus record for the number of human players
  (1-4 stars) and grants NO shared feature unlocks: `challengeDetermineUnlockedFeatures()`
  is skipped for Plus in both the offline (`challengeConsiderMarkingComplete`)
  and net (`netChallengeMatchEnded`) marking paths. Availability stays driven
  by the stock list.
- Future, not implemented: gate the Challenges+ menu behind completing all
  stock challenges with at least one star (any tier), and make custom weapons
  the Plus unlock tiers.

## Network

RULES and MATCH_END carry `u8 challengemode` (protocol 39). Clients set the
mode from RULES and mark into that dataset from the verdict, then restore their
own menu mode. The lobby's Game dropdown has a "Challenge+" option. The gate
`tools/ci/netchallengetest.sh` has a `plus` case asserting the generated name,
the challenge's own arena, both machines marking the Plus record, and that the
standard record is untouched.
